## Problem Statement

课程项目需要一个可换机复现的校园二手交易平台，满足异构分类属性、中文同义词搜索、卖家当前信息、改价历史、并发成交正确性及存储层自动下架等要求。立项时仓库只有要求和设计文档，没有可运行应用和测试。学生需要发布闲置商品、浏览搜索并由卖家确认线下成交，验收人员需要可执行的功能验证入口和可靠的数据库证据。

## Solution

交付 Go + Gin + MongoDB 的 V1 功能基线，通过 REST API 和 Swagger UI 操作全部 8 项核心功能，提供种子账号认证、可复现种子数据、Docker Compose 启动与导入命令及 Go 功能和并发正确性测试。先验证本地 MongoDB Search 和 TTL 独立在售条目方案，再实现功能；实验过程以 Markdown 记录。V1 不承诺已经完成 V2 正式性能验收。

## User Stories

1. As a 验收人员, I want 一条命令启动完整环境, so that 我能在另一台具备所需运行条件的机器复现项目。
2. As a 验收人员, I want 一条命令生成并导入种子数据, so that 我无需手工配置测试内容。
3. As a 验收人员, I want 固定随机种子和可配置时间基准, so that 数据特征和实验初始状态可复现。
4. As a 验收人员, I want 初始化拒绝非空实验数据库且重置必须显式指定, so that 重复运行不会无意追加或删除数据。
5. As a 学生, I want 使用种子账号登录并在 Swagger UI 中输入访问令牌, so that 我能执行需要身份的操作。
6. As a 卖家, I want 从平台维护的分类中选择商品类别, so that 商品进入正确分类。
7. As a 卖家, I want 填写分类定义的属性及受限扩展属性, so that 教材、自行车和数码商品能表达不同信息。
8. As a 卖家, I want 发布含中文标题、描述、挂牌价、统一新旧程度和 1–9 个图片地址的商品, so that 学生能了解我的闲置物品。
9. As a 学生, I want 按分类以发布时间倒序浏览有效在售商品, so that 我先看到最近发布的商品。
10. As a 学生, I want 使用稳定的游标分页, so that 发布时间相同的商品仍有确定顺序。
11. As a 学生, I want 用一个关键词同时搜索标题与描述, so that 我能找到相关商品。
12. As a 学生, I want 搜索单车时找到自行车或脚踏车, so that 同义表达不会阻碍发现商品。
13. As a 学生, I want 获得搜索命中总数和按相关性排序的前 20 条, so that 我能判断搜索范围并查看最相关结果。
14. As a 学生, I want 看到命中的标题或描述字段及片段, so that 我能理解结果为什么相关。
15. As a 学生, I want 搜索结果排除校验时已成交或到期商品, so that 我不会把无效商品误认为在售。
16. As a 学生, I want 一次详情请求看到完整商品、图片、卖家当前信息和最近改价记录, so that 我无需拼接多个请求了解商品。
17. As a 卖家, I want 修改本人昵称和头像, so that 商品详情展示我的当前资料。
18. As a 学生, I want 查看卖家有效在售商品、已完成交易数和当前信用分, so that 我能了解卖家的情况。
19. As a 卖家, I want 修改我的有效在售商品价格并保留旧价、新价和时间, so that 价格变更可追溯。
20. As a 学生, I want 详情展示最近 5 次改价并能分页查看更多历史, so that 历史完整但详情不会无限增长。
21. As a 卖家, I want 为另一已注册用户确认线下成交并提交成交价, so that 商品记录与实际交易一致。
22. As a 卖家, I want 成交价可以不同于挂牌价且精确到分, so that 线下议价能被准确记录。
23. As a 卖家, I want 商品成交信息、在售资格、成功记录和成交数共同提交, so that 不会出现部分成功。
24. As a 验收人员, I want 同一商品并发确认时只有一次成功, so that 我能证明没有超卖。
25. As a 卖家, I want 同一幂等键和内容的重试返回原结果, so that 网络重试不会重复成交或计数。
26. As a 卖家, I want 同键不同内容被拒绝且不同卖家的键互不干扰, so that 幂等结果不会被错误复用。
27. As a 验收人员, I want 成功和经过校验的业务失败形成交易记录, so that 30 万条交易记录能被准确解释。
28. As a 学生, I want 到期商品立即退出在售浏览、搜索、统计且不能成交, so that 过期商品不会继续被交易。
29. As a 卖家, I want 下架后仍保留商品档案及改价历史, so that 历史资料不会被清理丢失。
30. As a 验收人员, I want 看到 TTL 最终删除独立在售条目的数据库证据, so that 自动下架由存储层完成而非应用定时扫表。
31. As a 学生, I want 指定分类按统一新旧程度统计有效在售数量, so that 不同商品的品相数量可比较。
32. As a 验收人员, I want 数据包含异构属性、变化过的卖家信息、中文错别字和同义词及改价历史, so that 测试不只覆盖干净数据。
33. As a 验收人员, I want 每项核心功能有可执行验证入口, so that V2 能直接复用并记录实测结果。
34. As a 维护人员, I want 非本人修改及确认成交被拒绝, so that 商品所有权受到保护。
35. As a 维护人员, I want 分类规则变化后旧商品仍可读而新写入按当前规则校验, so that 分类演化不会破坏已有数据。

## Implementation Decisions

- 核心模块覆盖环境启动、种子导入、认证及卖家资料、分类属性、商品及改价历史、搜索、成交和统计。以 Go + Gin 提供 REST API，使用 OpenAPI / Swagger UI，不开发独立网页前端。
- Docker Compose 使用本地 `mongodb/mongodb-atlas-local`，固定实际验证过的镜像版本并配置事务所需环境；不使用占位版本或未经验证的兼容性声明。
- 第一实施关卡验证中文分析与版本化同义词表、标题及描述的字段命中片段、有效在售过滤和总数；同时验证 TTL 到期清理与事务。先用小规模案例检查行为，再用规定种子规模验证可用性并记录耗时。失败则重新讨论相关 ADR，不静默换用其他搜索或定时扫表方案。
- 商品档案保留商品、成交信息及历史；独立在售条目承载出售资格和到期时间，TTL 只删除条目。所有在售操作同时校验期限，不将 TTL 清理延迟当作继续出售的许可，不依赖应用定时任务扫描全表。
- 在售期限为发布时间加 60×24 小时，到期时刻及以后不得成交；改价不续期。V1 不支持重新上架、补录成交时间或撤销成交。成交时间为服务端确认时间。
- 平面分类由平台维护，定义属性类型和必填要求，也允许额外属性。额外属性仅限字符串、数值、布尔值及这些类型的数组，禁止嵌套对象；数量和长度限制须在接口契约中明确并验证，不覆盖价格、图片、新旧程度等标准字段。规则调整后历史可读，新建及修改按当前规则校验。
- 商品包含 1–9 个 HTTP/HTTPS 图片地址，只保存地址且不检查实际可访问性。新旧程度必填，统一为全新、几乎全新、轻度使用、明显使用；其他分类品相描述属于补充属性。
- 浏览以发布时间及商品 ID 倒序游标分页，默认 20 条、最多 100 条。分类统计仅针对指定分类的有效在售商品，不涉及子分类。
- 搜索只面向有效在售商品，查询标题及描述，使用中文分词和指定同义词集合，按相关性返回前 20 条、命中总数、`matchedFields` 和片段。标题与描述可同时命中，同义词命中也计入；不要求逐词评分解释或错别字纠正。
- 接受搜索收录短暂延迟；数据库当前在售资格校验适用于结果和总数，不能只过滤前 20 条而沿用过滤前总数。过滤不能无故漏掉排序后仍合格的后续候选。请求不承诺跨整个搜索的事务快照，每条结果在校验时必须有效在售；验证这一处理的实际代价。
- 详情一次请求返回完整商品资料、图片、卖家当前资料及最近 5 次改价，更多历史单独分页。首次挂牌价单独保留；每次实际改价永久记录旧价、新价及时间，相同价格不新增记录。
- 只有卖家可以修改本人有效在售商品及确认成交。买家须为其他已注册用户，禁止自买自卖；成交价可不同于挂牌价，使用人民币、精确到分且大于零。
- 成交以数据库条件更新裁决竞争；商品成交信息、在售条目移除、成功交易记录及卖家成交数在同一事务中提交，全部成功才返回成功，不允许状态或计数部分更新。
- 成交必须携带卖家范围内的幂等键。同键同内容返回原结果，同键不同内容拒绝，成功和业务失败结果随交易记录保留；并发重试不能重复写记录或增加成交数。
- 交易记录仅覆盖通过身份和参数校验的业务尝试，包括成功及已成交、已下架或到期等失败。认证、参数及基础设施错误进入日志；幂等重试不增加记录。事务回滚和业务失败不得增加卖家成交数。
- 详情和主页读取卖家当前昵称、头像及信用分，在售数量基于当前有效资格计算。V1 支持修改本人昵称和头像，信用分采用可复现种子值，不引入评价或自动信用算法。
- V1 仅使用种子账号登录，密码安全哈希，提供有有效期的访问令牌及 Swagger UI 认证入口；身份由令牌确定，不能信任请求中任意指定的卖家身份。
- 默认种子规模约 10,000 用户、20,000 在售商品、180,000 历史成交商品及 300,000 交易记录，成功记录对应历史成交商品，其余为业务失败。各商品具有 1–9 个图片地址，平均改价 2–3 次；包含分类属性差异及变化、卖家资料变化、中文错别字和同义词。历史价格、成交数、交易记录和在售资格彼此一致。
- 固定随机种子和可配置时间基准；初始导入仅允许空实验数据库。显式 `--reset` 仅作用于指定实验数据库，非空数据库默认拒绝，不默认全局清库。压测数据独立生成并支持恢复同样初始状态，正式压测运行属于 V2。
- HTTP 状态、业务错误类型、输入限制、令牌期限和游标格式须由 OpenAPI 明确；本 spec 未指定的可逆细节由实现确定，不能改变已确认的业务语义。

## Testing Decisions

- 用户已确认主要测试边界为真实 HTTP API，Go testing 驱动真实 MongoDB/Search 环境，尽可能通过请求和响应验证外部行为。认证、卖家资料、商品、改价、浏览、搜索、成交及统计均在该边界测试，不模拟数据库来代替事务、Search 或 TTL 验证。
- 立项时仓库没有应用代码、测试或现成测试边界可复用。必要的补充边界仅为 Compose 启动、种子 CLI 和数据库外部观察；数据库观察用于核验持久化不变量、种子规模及 TTL 物理清理，不绑定内部函数或聚合阶段实现。
- 全部 8 项核心功能各有可执行验证入口：发布、分类浏览、搜索、详情、卖家主页、成交、自动下架、分类统计。V1 验证功能，V2 用统一方法完成正式耗时及资源测量。
- 认证与授权：正确及错误登录、缺失或过期令牌、非本人改价和成交、本人资料修改与他人资料保护；认证及参数失败不能生成交易记录。
- 发布与属性：各类异构属性、必填与类型错误、额外属性边界、标准字段覆盖、嵌套对象拒绝、图片数量 0/1/9/10 及非 HTTP/HTTPS 地址、统一新旧程度非法值。分类规则变化后旧数据可读、新写入遵守新规则。
- 浏览与统计：分类隔离、发布时间相同的确定排序、默认与最大分页规模、静态数据分页不重复不遗漏；并发新增时不承诺分页快照。四个新旧档位计数与已成交和已到期排除。
- 搜索：固定同义词案例覆盖自行车／单车／脚踏车，分别命中标题、描述及两者；验证总数、最多 20 条及片段。候选中混入无效商品时，总数及结果均正确过滤，仍有足够合格候选时返回满额结果。等待索引就绪后断言，不把固定短暂等待视为同步保证；错别字存在于数据不意味着必须命中。
- 详情与主页：完整商品和图片、当前卖家资料、最近 5 次改价及历史分页、首次挂牌价与改价区分、同价修改不增加历史、过期不能改价、成交数与有效在售数正确。
- 成交：有效交易、挂牌价与成交价不同、非法价格、自买自卖、不存在买家及非所有者拒绝；确认时间和金额精确到分。多个并发请求竞争同一商品必须恰好一次成功、一份成功交易记录且成交数仅增加一次。
- 幂等：串行及并发同键同内容返回同一结果，不重复计数；同键不同内容拒绝；不同卖家相同键互不干扰；业务失败重试返回原结果。使用新键竞争已成交商品时记录业务失败。
- 事务失败：通过可控数据库故障或失败注入验证成交未完成提交时没有部分状态、成功记录或计数；测试应断言可观察的持久化结果，故障控制方式由实现选择，不要求增加公开测试接口。
- 到期：预置过去及近期到期条目，验证期限前、恰好到期及之后的业务边界，包含并发成交与到期竞争。即使 TTL 尚未清理，到期商品仍不能浏览、搜索、统计或成交。
- TTL：真实存储层最终删除在售条目，商品档案及历史保留；记录清理证据及实测延迟。使用有界轮询及明确诊断超时避免测试挂起，不将测试超时误写为业务清理时限；不依赖应用定时扫描。
- 种子与部署：换环境启动并等待数据库/Search 就绪，导入后核验规模、数据特征和跨记录一致性；同随机种子及时间基准可复现，非空拒绝、显式重置受限。完整数据与较小功能测试数据用途清楚区分。
- V1 完成标准为上述外部行为验证通过，核心功能均可执行，部署与导入可复现，索引及结构选择有说明，先行可行性验证有记录。不得将 V2 的 30,000 次成功成交压测或资源实测宣称为已完成。

- V3 Cobra CLI、Bubble Tea、独立网页前端。
- 在线支付、库存预占、订单履约、站内消息或联系系统、评价与信用算法。
- 公开注册、学校统一登录、短信验证、找回密码、刷新令牌及退出后的令牌撤销。
- 分类层级、重新上架、撤销成交、成交时间补录、图片上传及图片地址可达性检查。
- 任意中文词汇的同义理解、错别字纠正、逐词搜索评分解释、即时搜索收录及请求级搜索快照。
- Word 报告及学校封面模板排版；本轮报告为 Markdown。

## Further Notes

- 此 spec 根据已最终确认的设计访谈合成，遵循项目领域术语及关于卖家确认线下成交、下架保留历史、本地 Search、独立在售条目和成交事务的 ADR。
- 作业数据规模与压测成功量存在不同口径：V1 默认约 20,000 件在售商品；V2 另备至少 30,000 件可成交商品，并明确实测规模。约 300,000 条交易记录不代表同样数量的成功成交。
- 课程要求的正式性能与报告交付在 V2 完成；V1 不称为完整可验收课程交付。
- Markdown 报告持续记录真实验证结果，不编造耗时、兼容性、存储或内存数据。
- 可行性验证若发现本地 Search、同义词片段或有效性过滤不能满足需求，应携带实验结果重新讨论相关决策，而非降低需求后仍标记完成。
