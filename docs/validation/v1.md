# V1 功能基线与换环境验收（#13）

## 复现入口与前置条件

```sh
scripts/validate-v1.sh
# 自定义报告路径：scripts/validate-v1.sh /tmp/v1-run.md
```

需要 Linux Docker Engine、Compose v2 或更新版本、Bash、Git，以及下载固定镜像和 Go 模块的网络。Go 在固定的构建镜像中运行，宿主无需安装 Go、MongoDB 或 mongosh。Swagger UI 从 unpkg 下载固定版本资源，浏览器查看需要网络；API 与机器可读 OpenAPI 在本地运行。当前验证的是 Linux x86_64，不据此承诺其他架构。

完整种子包含 10,000 用户、20,000 在售商品、180,000 历史成交商品、300,000 交易记录、500,000 改价记录。建议预留至少 8 个 CPU、16 GiB 可用内存、20 GiB 可用磁盘用于数据库/Search、镜像构建与完整种子；这是运行预算建议，不是测出的最低配置。实际机器与 Docker 分配资源、磁盘空间记录在原始报告中。本轮不提供峰值资源或性能容量结论。

入口为每次运行创建独立 Compose 项目、网络和三个命名卷，无宿主端口，不读取开发环境数据库或残留卷；启动前拒绝同项目卷复用。退出时删除本次项目容器与卷（成功及失败均清理），保留 Markdown 原始输出，失败追加服务日志。中断清理失败时，用报告中的准确项目名执行 `docker compose -p <项目名> -f compose.v1.yaml down --volumes --remove-orphans`。不要删除其他项目卷。

脚本按当天 UTC 零点生成并记录 `--base-time`，随机种子为 42。种子 CLI 的默认固定日期没有改变。业务和 TTL 仍使用真实时钟，复现时不能把旧数据的到期当成导入错误。完整导入不具有全库原子性，CLI 成功及只读规模检查通过后才启动业务服务。

也可在一个**新项目**逐条操作（保留数据时适用）：

```sh
# 使用从未使用过的项目名；所有后续命令必须用相同的 -p。
# 一条命令启动数据库；--wait 等待数据库健康。
docker compose -p campus-v1-manual -f compose.v1.yaml up -d --build --wait mongo
# 一条命令构建并导入完整种子，不使用 --reset。
# 将日期替换为接近当前 UTC 日期的基准并记录。
docker compose -p campus-v1-manual -f compose.v1.yaml run --build --rm --no-deps market seed --mode full --random-seed 42 --base-time 2026-10-10T00:00:00Z
# 一条命令启动完整服务并等待 HTTP 健康；不等于 Search 收录就绪。
docker compose -p campus-v1-manual -f compose.v1.yaml up -d --build --wait
# 等待全规模 Search 命中稳定，并执行 HTTP 验收。
docker compose -p campus-v1-manual -f compose.v1.yaml run --build --rm --no-deps -e V1_API_URL=http://market:8080 -e V1_DB_NAME=campus_v1 verify test -v ./internal/market -run '^TestV1FullSeedHTTP$' -count=1 -timeout=8m
```

导入须发生在业务 API 启动前；非空库拒绝导入，显式 `--reset` 仅重置 `campus_v1`。手工命令不自动清理。`compose.v1.yaml` 不开放宿主端口；日常 Swagger 使用根 `compose.yaml` 的 http://localhost:8081/docs，账号 `seller` / `buyer`、密码 `CampusDemo123!`。根环境必须先导入空 `campus_market`，再启动 `market`，已有数据不要再次默认导入。

## 八项核心功能与验证入口

所有 HTTP 功能均通过真实请求验证，不模拟 MongoDB/Search。统一入口先观察完整种子持久化一致性，再针对部署的完整种子 API 执行 `TestV1FullSeedHTTP`。其后完整测试套件在独立测试库中验证所有权、幂等、并发、事务回滚与到期边界；完整种子 HTTP 测试还将一件已知种子自行车设置为到期，验证浏览全分页、Search 总数、统计、主页排除，拒绝成交/改价并保留详情/历史；通过 MongoDB 外部准备到期夹具，不添加公开测试接口。其他边界夹具不冒充完整种子数据。到期采用可控时间及真实 TTL 外部观察，避免等待 60 天。

在已启动的根环境，可用 `docker compose run --rm --no-deps verify test -v ./internal/market -run '<下表测试名>' -count=1 -timeout=8m` 单独复验；每个测试自行创建并清理数据库。

| 功能 | HTTP 入口 | 可执行测试/入口 | 索引或结构理由 |
|---|---|---|---|
| 发布 | `POST /products` | `TestPublish`、`TestPublishing`；全规模 `TestV1FullSeedHTTP` | 分类规则校验异构属性；事务共同写商品档案和独立在售条目，避免部分发布 |
| 分类浏览 | `GET /products?categoryId=bicycles` | `TestBrowse`；全规模 HTTP | `category_browse` 按分类、成交状态、发布时间及 ID 排序，游标同时间确定排序；资格和期限额外校验 |
| 搜索 | `GET /search?q=单车` | `TestSearch`；全规模 HTTP | `products_v1` 标题/描述 `lucene.smartcn` 与版本化 `synonyms_v1`；数据库验证当前资格后才计算总数及前 20，容许收录延迟 |
| 详情 | `GET /products/{id}` | `TestDetail`、`TestPrice`、`TestSellerChangesPrice`；全规模 HTTP | 商品档案永久保留，读取当前用户资料；`priceChanges(productId,changedAt,_id)` 支持最近 5 条和历史游标 |
| 卖家主页 | `GET /users/seller/home` | `TestSellerHome`；全规模 HTTP | `seller_browse` 按卖家和发布顺序检索；当前资料来自 users，成交数随成交事务更新，在售数校验期限 |
| 成交 | `POST /products/{id}/sale` | `TestSale`；全规模 HTTP | 条件更新与多文档事务裁决唯一成交；卖家范围内幂等键唯一索引防止重试重复记录/计数 |
| 自动下架 | 所有在售入口及保留的详情/历史 | `scripts/validate-expiry.sh`、`TestExpiry`、`TestSaleExactExpirationHTTP`、`TestSaleTransactionRetryAcrossExpirationHTTP` | `listings.expiresAt` 零秒 TTL 只删除资格；即时期限校验排除清理延迟，保留档案/图片/价格链，无应用扫表 |
| 分类统计 | `GET /categories/bicycles/condition-counts` | `TestConditionCounts`；全规模 HTTP | 按指定分类过滤，联查当前资格并按四档品相聚合；复用分类过滤结构，不引入物化过期计数 |

完整测试包含认证与参数失败不写交易记录、跨用户资料保护、非法属性/图片、规则演化、静态分页不遗漏、同价不新增历史、同键异内容拒绝、不同卖家同键隔离、业务失败重试、同商品并发唯一成交、事务回滚和跨到期重试。具体测试输出保留在报告，不能只用 HTTP 200 代替业务断言。

OpenAPI 和 Swagger HTML 的 HTTP 契约测试由完整套件执行；浏览器点击不由此自动推断完成。种子全规模只读核验复用 `scripts/check-seed.js`，验证数量、图片限制、改价链、成功成交关联和卖家计数；在验收 HTTP 修改数据之前执行。Search 用最多 3 分钟轮询等待预期命中 6,667，失败记录最后响应；TTL 采用 3 分钟有界观察并记录实际删除延迟，均不是业务 SLA。
