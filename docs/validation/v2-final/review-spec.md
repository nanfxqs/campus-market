## Spec

1. **P2 — Unified stage IDs are not bound to measured configurations or paired detail sequences.** `scripts/validate-v2.py:68–73,99–105` checks ID presence and evidence kind, but passes no expected configuration/state/pattern to the artifact validators. Consequently, pointing every sale ID at A1 and every detail ID at A-hotspot still satisfies the stage checks and matching sale fingerprints; it does not verify three independent A/B/C rounds or the requested cold/hot/dispersed experiments. The detail validator also does not compare paired pool hashes, actual initial counts, or cold-empty/hot-prewarm records. Spec: “A/B/C 各做三轮正式验收” and “同组不同配置的商品序列相同。冷缓存指计时开始为空…热缓存指事先访问该组涉及商品后不清空”. Bind IDs to artifact configuration/state/pattern and distinct round identities, verify full scale and preparation records, and compare same-pattern pool hashes. Add public CLI negative tests for substituted/duplicated stages and mismatched pools. Existing delivered experiments appear correct; this is an acceptance-entry hole.

2. **P2 — Competition verifier ignores authoritative database facts and same-key receipts.** `scripts/validate-v2.py:55–64` loads `database-facts.jsonl` only to count lines, checks database values copied into summary.json, omits seller counter increments, accepts any 409 as a business conflict, and returns sameKey without validating its receipts or database facts. Corrupted/missing same-key evidence or incorrect seller increments can therefore pass the purported raw verification. Spec: “逐组核验成功记录、档案状态、资格移除与卖家计数” and “另验证同键重试多响应单事实”. Recompute groups and same-key/changed-content outcomes from raw receipts and parsed read-only database outputs, including linked transaction ID, buyer/price, seller +1, business error codes, and C upstream evidence; reject mismatches with summaries. Add negative artifact tests. The original experiment runner enforces these facts; the unified verifier does not.

No concrete production behavior mismatch or scope creep found. Natural Redis fallback, early completion under the 600-second cutoff, doubled C application resources, and absent second-machine validation are consistent with the confirmed spec and reported honestly.
