校园二手交易平台以 MongoDB 保存商品档案、在售资格和交易事实，MongoDB Search 提供中文分词与同义词，Redis 作为可失效的商品资料缓存。当前机器的 A/B/C 各三轮成交均独立完成 30,000 件新增按时成交，全部外部数据库核验通过；缓存实验没有证明必然加速。报告正文集中分析 NoSQL 数据模型、一致性和实测代价，代理实验的完整材料保留在链接中。

## 数据库选型与模型

商品分类具有不同属性：教材有作者，自行车有车型，统一标准字段之外允许受限扩展属性。文档模型可保留这些差异，类别文档约束标准属性类型与必填项。价格与成交价使用整数分；图片为 HTTP/HTTPS 地址，不声称已验证远端图片。MongoDB 的单文档条件更新、唯一键和多文档事务共同保证成交事实。Redis 不裁决成交，缓存故障不能改变数据库成功事实。跨文档事务有额外成本，应围绕必要不变量使用，而不能据此声称分散写入天然便宜。[MongoDB 事务说明](https://www.mongodb.com/docs/manual/core/transactions/)。

`products` 是保留的商品档案，包含分类、标题、描述、品相、图片、属性、卖家、价格、发布时间、截止时间与成交信息；`listings` 是独立在售资格 `{_id, expiresAt}`。到期立即失去资格，TTL 最终仅删除 listing，档案、图片与价格历史保留。把 TTL 直接建在商品档案上会违背下架保留要求。实际授权查询和成交同时检查期限，因后台删除存在延迟。[TTL 官方机制](https://www.mongodb.com/docs/manual/core/index-ttl/)。

`users` 存当前资料、预设信用与累计成交数，密码哈希不公开；`sessions` 存令牌哈希及期限，MongoDB 共享会话使两实例无需粘滞。`transactions` 记录通过认证和参数校验后的业务尝试，不等于支付订单。卖家与幂等键的哈希作为唯一 `_id`：同键同内容重放原结果，同键改商品、买家或价格拒绝。成交事务原子提交商品 sold、listing 删除、成功记录和卖家计数，事务失败全部回滚。`priceChanges` 独立保存实际改价，首次挂牌价不算改价历史；改价不续期。类别变化与种子元数据用于规则示例及复现。决策见 [ADR](adr/) 和 [术语](../GLOSSARY.md)。

## 八功能的索引与结构理由

| 功能 | 主要结构/索引 | 理由与限制 |
|---|---|---|
| 发布 | categories `_id`；products/listings `_id`；两记录事务 | 按当前分类规则验证，创建档案与资格不能部分成功 |
| 分类浏览 | `category_browse {categoryId:1,sold:1,publishedAt:-1,_id:-1}`，listing `_id`关联 | 分类等值和未成交范围，时间/ID确定倒序游标；期限仍需过滤，不声称覆盖查询 |
| 中文搜索 | `products_v1` title/description、smartcn；版本化自行车/单车/脚踏车同义词 | 搜索候选按排名读取，批量校验当前Mongo档案与资格，精确总数后只为选中20条生成高亮 |
| 详情 | product/user/listing `_id`；`priceChanges {productId:1,changedAt:-1,_id:-1}` | 当前动态字段、卖家资料和最近5次改价直接来自Mongo，只有稳定资料可缓存 |
| 卖家主页 | `seller_browse {sellerId:1,sold:1,publishedAt:-1,_id:-1}`；users `_id` | 按卖家范围查询有效资格，facet计数在整套有效商品上计算，不把剩余页数当总数 |
| 成交 | transaction `_id`唯一性、条件unsold更新、多文档事务 | 唯一键处理重试，条件更新处理竞争，四项事实原子提交；不使用Redis锁 |
| 自动下架 | listings `{expiresAt:1}` TTL0；所有入口即时期限比较 | 资格物理清理与业务拒绝分开，永久档案不参加TTL |
| 分类统计 | 分类/未成交索引前缀，listing关联，condition分组 | 对实际有效商品分组并补齐4档，不依赖易失缓存计数器 |

此外 users.username 唯一索引用于登录；sessions.expiresAt TTL0负责最终清理，授权仍校验真实截止时间。没有额外虚构的幂等复合索引或统计索引。索引声明说明设计意图，不等于已用 explain 证明每条请求的执行计划。Search 曾为大量历史候选提前生成高亮，实测导致超时；改为无高亮候选及当前资格核验，再对选中页生成真实高亮，保持精确有效总数与排名。详细前后探针及初始失败见 [Search实测](validation/v2-lb21/README.md)。

## Redis资料版本缓存实测
