# 开发与验收计划

## 已确认的迭代边界

- V1 为功能基线版：先验证 MongoDB Search 与存储层自动下架的可行性，再完成数据建模、种子数据、8 项核心功能、REST API、Swagger UI、功能与并发正确性测试及一键部署。
- V2 完成正式压测、吞吐量与 P95/P99、存储与内存实测、8 项功能的可执行脚本与耗时、课程实验报告；先测基线，再按瓶颈决定是否增加 Redis、Nginx 和多个 Gin 实例。
- V3 为可选 CLI 扩展，通过 HTTP 调用现有 API，使用 Cobra 和表格输出，复杂交互有实际需求后再考虑 Bubble Tea。

## 已确认的业务与验收口径

- 卖家确认线下成交，提交买家与成交价；商品只能成功成交一次。
- 交易记录包含成功和失败的成交尝试。种子数据约 18 万件历史成交商品对应成功记录，总计约 30 万条交易记录，其余为失败记录。
- 正式压测以 50 并发在 10 分钟内完成 3 万次成功成交为目标，另备至少 3 万件可成交商品，并明确报告运行时数据规模。
- 同商品竞争测试单独执行；报告成功、冲突与其他失败结果，分别说明耗时口径。
- 下架保留商品及历史，退出在售浏览、搜索和统计，并禁止成交；V1 不支持重新上架。
- V1 提供最小身份认证、所有权校验与种子账号；不包含学校统一登录、短信验证及找回密码。

## 确认状态与验证前置条件

设计访谈的决策与完整方案均已由用户最终确认。实现前须完成 MongoDB Search 和 TTL 在售条目方案的可行性验证；若验证不通过，应重新讨论相关决策，不静默替换方案。

## 第二轮已确认

- Docker Compose 使用本地 `mongodb/mongodb-atlas-local` 镜像，固定经验证的版本；先以要求的种子规模验证搜索能力与配置。
- 保留商品档案，将在售资格存入独立条目，由 TTL 删除到期条目；验证所有在售查询与成交的一致性后正式落定实现。
- 在售期限为发布时间加 60×24 小时；到期立即禁止成交，浏览、搜索和统计排除到期商品，TTL 负责后续物理清理。改价不续期，V1 不支持重新上架。
- 搜索只覆盖有效在售商品，保证中文分词和指定同义词集合，暂不承诺错别字纠正；按相关性返回前 20 条及有效在售范围内命中总数。
- 搜索结果包含 `matchedFields` 和命中片段，标题与描述可同时命中，同义词命中也计入；不要求逐词解释评分。
- 平台维护分类及属性类型、必填要求，允许额外属性；历史商品可读取，新增或修改按当前规则验证。
- 所有商品必填统一新旧程度：全新、几乎全新、轻度使用、明显使用；分类属性可补充品相说明。
- 交易记录只记录通过身份和参数校验的业务尝试，包括成功及已成交、已下架或到期等业务失败。认证、参数及基础设施错误记录日志；相同幂等键重试返回原结果，不新增交易记录。

## 第三轮已确认

- 成交以条件更新裁决竞争；商品成交信息、在售条目移除、成功交易记录与卖家成交数在同一数据库事务中提交，全部提交成功才返回成功。
- 买家必须为其他已注册用户，禁止自买自卖。成交价可不同于挂牌价，必须大于零，以人民币分为单位准确存储。
- 成交时间由服务端记录为确认时间，V1 不支持补录时间及撤销成交。
- 成交必须携带按卖家隔离的幂等键；同键同内容返回原结果，同键不同内容拒绝。成功及业务失败结果随交易记录保留，修改请求须用新键。
- 首次挂牌价单独保存；实际改价永久记录旧价、新价和时间，相同价格不新增记录。详情默认返回最近 5 次，另提供历史分页；只有卖家可修改其有效在售商品。
- 详情及主页展示卖家当前信息；在售数量按有效在售资格计算。V1 提供修改本人昵称、头像的接口，信用分为可复现的种子值，不引入评价及信用算法。
- V1 分类为平面结构，浏览按发布时间和商品 ID 倒序使用游标分页，默认 20 条、最多 100 条；分类浏览和统计只针对指定分类。
- 接受搜索收录的短暂延迟；返回前校验数据库当前在售资格，命中总数与前 20 条使用相同有效性条件，并在可行性验证中测量代价。
- 压测以 HTTP 客户端端到端耗时报告吞吐量、P95/P99，附服务端辅助指标。基线与优化使用相同机器、数据和负载；报告 CPU、内存、磁盘和软件版本，分别报告数据库、搜索进程、应用内存和相关持久卷占用。

## 第四轮已确认

- 种子生成使用固定随机种子和可配置时间基准；初始化命令只允许写入空实验数据库。重置必须显式指定 `--reset`，只作用于指定实验数据库。
- 压测数据单独生成，每轮压测前恢复相同初始状态。
- V1 仅支持种子账号登录，密码安全哈希，提供有有效期的访问令牌，Swagger UI 支持令牌认证；暂不提供公开注册、刷新令牌或退出后的令牌撤销。
- 扩展属性只允许字符串、数值、布尔值及这些类型的数组，不允许嵌套对象，并限制数量、名称和值长度。标准字段独立保存，不能被扩展属性覆盖。
- 每件商品包含 1–9 个 HTTP/HTTPS 图片地址，不验证图片实际可访问性。
- 同义词表和固定验收案例版本化，至少覆盖自行车／单车／脚踏车，验证标题、描述及同时命中。搜索总数和结果采用相同有效性条件，但不承诺请求级事务快照；每条结果在校验时有效在售。
- 自动下架验收预置已过期及即将到期条目，证明期限立即阻止在售查询与成交，并证明 TTL 最终删除条目而商品档案仍保留；记录数据库证据及实际清理延迟，不承诺固定清理时限。
- 不增加作业未要求的 P95/P99 门槛，报告实测值及错误率；8 项功能脚本使用统一测量方法，保留原始输出。
- 课程实验报告先采用 Markdown，持续记录选型、设计、实验及实测结果；本轮不制作 Word 文档，学校封面模板不作为当前工作依赖。
